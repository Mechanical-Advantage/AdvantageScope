# mur-voir 0.2.0

This release prepares the dashboard for the MUR cellular telemetry API and brings together the completed trackside and lap-analysis work.

## Changes

- Track Map and Laps share one Track and laps tab with Map, Laps and adjustable Split views. Existing layouts restore their previous view.
- The shared session timeline remains available across time-based analysis tabs. Optional lap time and distance comparison modes are labelled experimental.
- Trackside replaces the health strip with draggable readout tiles, an optional graph and saved critical limits. Active DBC faults appear above every desktop tab.
- Driver Inputs shows steering, throttle and brakes. Car Dynamics shows measured wheel speeds, steering, yaw, acceleration and damper positions.
- Live lap updates process changed samples and reuse completed results. Long sessions no longer require a full lap analysis on every update.
- Rolling history retention keeps bounded lap context and rebuilds it at 30-second checkpoints, avoiding a full re-analysis on every one-second trim.
- Saved layouts resolve live and recorded fields by DBC signal name. Lap inputs subscribe only while a lap view needs them.
- Opening a recorded log after live telemetry clears the live clock and fits the recorded timeline.
- Release builds run the dashboard tests, mock-backend tests, Lite smoke test and a headless cellular API check. Download names now identify mur-voir and its platform.

## Connect over cellular

Join the MUR tailnet, open File > Connect, choose MUR Telemetry and enter the deployed backend's HTTP URL. The dashboard browses its catalogue, subscribes to active signals, requests recent history and reconnects automatically.

See [cellular connection and layout instructions](https://github.com/Melbourne-University-Motorsports/mur-voir/blob/v0.2.0/docs/cellular-telemetry.md).

## Downloads

Desktop installers are available for macOS and Windows on x64 and arm64, with AppImages for Linux x64 and arm64. The Lite ZIP runs through its included Node server and needs no npm installation. SHA256SUMS.txt contains archive checksums.

The desktop builds have no developer signing certificate or notarisation. Operating systems may ask you to approve the downloaded app. Keep original telemetry logs.

## Verification limits

The cellular check uses a local backend that implements the pinned MUR API. It covers five-minute history, selected subscriptions, connection loss, backend restart, duplicate deliveries and saved tab layouts. The Pi publisher, Ericsson cellular path, tailnet and deployed Azure backend require their own acceptance run. This release changes the dashboard only.

ROS 2, Foxglove, MCAP, point clouds and 3D remain on the experimental branch and are absent from this release. Trackside and Video are desktop-only.
