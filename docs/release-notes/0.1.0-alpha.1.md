# mur-voir 0.1.0-alpha.1

## What this is

MUR's telemetry dashboard, forked from AdvantageScope.
This first public alpha brings live signals, recorded logs, graphs, laps and ROS 2 3D into one workbench.

## Known limits

- The Mac DMG is Apple Silicon (arm64) only, unsigned by a developer certificate and not notarised. Copy the app to Applications. If macOS blocks it, run `xattr -cr /Applications/mur-voir.app`, then open it again. Clearing attributes and launching the packaged app was verified locally; a freshly downloaded quarantine prompt was not reproduced.
- Other platforms run from source; Windows/Linux builds were not tested for this release.
- Radio was tested against the Wireless-telem simulator, not real XBee hardware.
- MQTT direct is a debug source. The car-side cellular publisher is not built yet.
- `PEDAL_BrakePressure1` currently has an incorrect percent display profile; use its raw inspector value instead.
- This is an alpha: keep original logs. Large histories and hardware/network combinations need further testing.

## Run

Download `mur-voir-0.1.0-alpha.1-arm64.dmg` from this release, mount it and drag mur-voir to Applications.

Or, with Node.js 26 and npm installed, from a checkout of this version:

```sh
npm install
npm run compile
env -u ELECTRON_RUN_AS_NODE npm start
```

For a hardware-free overview, in another terminal in the checkout:

```sh
npm run mock-backend -- --sim-clock --lap-counter
```

In **File → Connect…** (Cmd/Ctrl+K), choose **MUR Telemetry**, address `http://localhost:8090`, then **Connect**. Use **View → Trackside Layout** for health tiles and graphs.

![Mock backend overview](https://raw.githubusercontent.com/Melbourne-University-Motorsports/mur-voir/v0.1.0-alpha.1/docs/screenshots/overview.png)

Lite is also available as `mur-voir-lite-0.1.0-alpha.1.zip`. Unzip into an empty folder; Node.js 26 is required, with no npm install:

```sh
node tools/lite-serve/main.mjs --port 5808 --backend http://127.0.0.1:8090
```

Keep the backend above running separately. Open `http://localhost:5808`; Connect with **MUR Telemetry**, address `http://localhost:5808`. The zip was unpacked and tested against the mock backend. To build Lite from source: `npm run lite-build`, then `npm run lite-serve -- --port 5808 --backend http://127.0.0.1:8090`.

## Connect to sim

From the mur-voir checkout, start the demo Foxglove WebSocket producer:

```sh
node tools/mock-ros.mjs
```

Connect settings: **ROS 2 (Foxglove WebSocket)**, address `ws://localhost:8765`. For a real ROS 2 system, use its running `foxglove_bridge` address instead (not tested here).

Add a **3D Field** tab. Drag `/vehicle/pose`, `/planning/path`, `/perception/cones` and `/lidar/points` from the tree into **Layers**; set **Fixed frame** to `map`.

![ROS 2 mock connected in 3D](https://raw.githubusercontent.com/Melbourne-University-Motorsports/mur-voir/v0.1.0-alpha.1/docs/screenshots/sim.png)

## Connect to radio telem

Install [uv](https://docs.astral.sh/uv/) and check out [Wireless-telem](https://github.com/Melbourne-University-Motorsports/Wireless-telem). In that checkout, run each command in a separate terminal:

```sh
uv run base-station --udp-port 15001 --output /tmp/live.jsonl
uv run telem --simulate-port 15000 --radio-udp 15001 --no-bms --log-dir /tmp/alpha-radio-logs
uv run can-simulator --udp-port 15000
```

In the mur-voir checkout:

```sh
npm run radio-bridge -- --input /tmp/live.jsonl --port 1885
```

Connect settings: **MQTT direct (debug)**, address `ws://127.0.0.1:1885`, topic filter `mur/signal/#`, mapping **JSON per signal**, username/password empty, **CAN timestamp unchecked**. The bridge follows new packets; it does not provide history. Expand `DASH` and drag `DASH_WheelSpeedFL` and `DASH_WheelSpeedFR` onto the graph's Left Axis.

The simulator commands were run from an unmodified Wireless-telem checkout, using an external uv environment and `--no-editable --frozen` to keep it untouched. No radio hardware was used. See [bridge details](../../tools/radio-bridge/README.md) for the serial hardware path.

![Wireless-telem simulator through base station and radio bridge](https://raw.githubusercontent.com/Melbourne-University-Motorsports/mur-voir/v0.1.0-alpha.1/docs/screenshots/radio.png)

## Connect to MQTT

From the mur-voir checkout:

```sh
npm run mqtt-mock
```

Connect settings: **MQTT direct (debug)**, address `ws://localhost:1884`, topic filter `mur/signal/#`, mapping **JSON per signal**, username/password empty, **CAN timestamp unchecked**. Expand `INVERTER` and drag `INV_MotorSpeedRPM` onto Left Axis.

![MQTT mock connected with motor speed graphed](https://raw.githubusercontent.com/Melbourne-University-Motorsports/mur-voir/v0.1.0-alpha.1/docs/screenshots/mqtt.png)

Stop demo producers and servers with Ctrl+C when finished.
