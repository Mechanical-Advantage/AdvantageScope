# ⚙️ Таңдамалы активтер {#custom-assets}

AdvantageScope тегіс алаң кескіндерінің, алаң үлгілерінің, робот үлгілерінің және джойстик конфигурацияларының әдепкі жиынтығын пайдаланады. Қарапайым активтер (мысалы, әмбебап алаңдар) бастапқы орнату құрамына кіреді. Егжей-тегжейлі активтер (мысалы, маусымға арнайы алаңдар) AdvantageScope интернетке қосылған кезде фонда автоматты түрде жүктеп алынады. Осы жүктеп алулардың күйін тексеру үшін «Қолданба»/«AdvantageScope» > «Активтерді жүктеп алу күйі...» басыңыз.

Қаласаңыз, көбірек опцияларды қосу үшін активтер жиынтығын баптауға болады. Пайдаланушы активтері қалтасын ашу үшін «Қолданба»/«AdvantageScope» > «Активтер қалтасын көрсету» басыңыз. Активтердің күтілетін пішімдері төменде анықталған. Анықтама ретінде [егжей-тегжейлі активтердің](https://github.com/Mechanical-Advantage/AdvantageScopeAssets/releases) және [жинақталған активтердің](https://github.com/Mechanical-Advantage/AdvantageScope/tree/main/bundledAssets) әдепкі жиынтығын қараңыз.

:::tip
Активтерді баламалы орыннан жүктеу үшін «Қолданба»/«AdvantageScope» > «Таңдамалы активтер қалтасын пайдалану» басыңыз. Таңдалған қалта бөлек ішкі қалталарда бірнеше активтерді орналастыруға болатын _негізгі қалта_ (parent folder) болуы керек. Бұл мүмкіндік таңдамалы активтерді робот кодымен бірге нұсқаларды басқару (version control) жүйесінде сақтауға мүмкіндік береді.
:::

## Жалпы пішім {#general-format}

Барлық активтер «TYPE_NAME» атау келісімі бар қалталарда сақталады. Қалта үшін пайдаланылатын NAME (атау) AdvantageScope арқылы көрсетілмейді. Мүмкін болатын актив түрлері:

- "Field2d"
- "Field3d"
- "Robot"
- "Joystick"

:::info
Қалта атауларының мысалдары: «Field2d_2023Field», «Joystick_OperatorButtons» немесе «Robot_Dozer».
:::

Бұл қалтада «config.json» деп аталатын файл және төменде сипатталғандай бір немесе бірнеше актив файлдары болуы керек. Конфигурация файлы әрқашан AdvantageScope көрсететін активтің атауын қамтиды. Бұл атау әрбір актив түрі үшін бірегей болуы керек.

```json
{
  "name": string // Бірегей атау, барлық актив түрлері үшін міндетті
  ... // Түрге байланысты конфигурация, төменде сипатталған
}
```

### Шолу {#overview}

Қалтада «model.glb» атауы бар үлгі болуы керек. CAD файлдары glTF пішіміне түрлендірілуі тиіс; мәліметтер алу үшін [бұл бетті](gltf-convert) қараңыз. Конфигурация файлы келесі пішімде болуы керек:

```json
{
  "name": string // Бірегей атау, барлық актив түрлері үшін міндетті
  "isFTC": boolean // Үлгі FRC алаңдарының орнына FTC алаңдарында пайдалануға арналған ба, жоқ па (әдепкі "false")
  "disableSimplification": boolean // Үлгіні қарапайымдатуды өшіру керек пе, міндетті емес
  "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // x, y және z осьтері бойымен айналу тізбегі
  "position": [number, number, number] // Метрдегі позиция ығысуы, айналудан кейін қолданылады
  "cameras": [ // Бекітілген камера позициялары, бош болуы мүмкін
    {
      "name": string // Камера атауы
      "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // x, y және z осьтері бойымен айналу тізбегі
      "position": [number, number, number] // Роботқа қатысты метрдегі позиция ығысуы, айналудан кейін қолданылады
      "resolution": [number, number] // Пиксельдегі ажыратымдылық, бекітілген пропорцияны орнату үшін пайдаланылады
      "fov": number // Градустағы көлденең көру өрісі
    }
  ],
  "components": [...] // «Топсалы компоненттер» бөлімін қараңыз
}
```

Тиісті позиция және айналу мәндерін анықтаудың ең қарапайым жолы — сынақ пен қателік әдісі. Түрлендірулер осы ретпен қолданылатындықтан, позициядан бұрын айналуды реттеуді ұсынамыз.

:::info
AdvantageScope өнімділікті арттыру үшін үлгі геометриясын автоматты түрде қарапайымдатады, мұнда егжей-тегжейлілік деңгейі таңдалған [рендеринг режиміне](/tab-reference/3d-field#rendering-modes) байланысты. Таңдамалы активтермен үлгіні қарапайымдату қажетсіз әсерлерді тудыратын жағдайларда екі шешімді пайдалануға болады:

- Белгілі бір сетканың (mesh) автоматты түрде жойылуын өшіру үшін сетка атауына `NOSIMPLIFY` жолын енгізіңіз.
- Бүкіл робот үлгісі үшін үлгіні қарапайымдатуды өшіру үшін конфигурациядағы `disableSimplification` опциясын `true` күйіне орнатыңыз.

:::

### Топсалы компоненттер {#articulated-components}

:::warning
Топсалы компоненттерді баптау күрделі әрі көп уақытты алуы мүмкін. **3D алаңында механизмдерді визуализациялауға** оңтайландырылған тәсілді ұсынатын AdvantageScope 3D [`Mechanism2d` қолдауын](/tab-reference/3d-field#2d-mechanisms) пайдалануды қарастырыңыз.
:::

Робот үлгілері механизм деректерін визуализациялау үшін топсалы компоненттерді қамтуы мүмкін (мәліметтер алу үшін [осы жерді](/tab-reference/3d-field) қараңыз). Негізгі glTF үлгісі ешқандай компоненттерді қамтымауы керек, содан кейін әрбір компонент бөлек glTF үлгісі ретінде экспортталуы тиіс. Компоненттер үлгілері «model_INDEX.glb» атау келісімін сақтайды, сондықтан бірінші топсалы компонент «model_0.glb» болады.

Компонент конфигурациясы роботтың конфигурация файлында беріледі. Компоненттер жиымы «components» кілті астында берілуі керек. AdvantageScope ішінде пайдаланушы тарапынан компонент позалары берілмеген кезде, компонент үлгілері роботтың әдепкі айналулары мен позициясын пайдаланып орналастырылады (жоғарыда қараңыз). Пайдаланушы тарапынан компонент позалары берілген кезде, әрбір компонентті роботтың бас нүктесіне әкелу үшін оның орнына «нөлденген» (zeroed) айналулар мен позиция қолданылады. Содан кейін әрбір компонентті роботтағы дұрыс орынға жылжыту үшін пайдаланушы позалары қолданылады.

:::tip
3D компоненттерін роботқа қатысты орналастыру кезінде координаттар жүйесінің бас нүктесі роботтың жарияланған позасына сәйкес келеді. Бұл поза әдетте нөлдік биіктікті пайдаланатынын ескеріңіз, бұл робот түбі емес (bellypan), еден жазықтығы болып табылады (әдеттегі 2D робот қозғалысы үшін).
:::

```json
"components": [
  {
    "zeroedRotations": { "axis": "x" | "y" | "z", "degrees": number }[] // x, y және z осьтері бойымен айналу тізбегі
    "zeroedPosition": [number, number, number] // Роботқа қатысты метрдегі позиция ығысуы, айналудан кейін қолданылады
  }
]
```

#### Баптау процесі {#setup-process}

Топсалы компоненттердің позицияларын калибрлеу үшін келесі процесті ұсынамыз:

1. Негізгі үлгі мен компоненттерді олардың дұрыс «әдепкі» позицияларында экспорттаңыз. AdvantageScope ішінде компонент позалары берілмесе, олар осылай рендерленуі керек.

2. Робот кодынан нөлденген 2D позасын жариялаңыз, содан кейін оны AdvantageScope ішінде робот позасы ретінде таңдаңыз. Алаңның бас нүктесін көрсететін «Осьтер» (Axes) 3D алаңына ауысыңыз.

3. Бүкіл робот дұрыс бағытталғанша роботтың жалпы айналуларын (компоненттерді емес) реттеңіз. Содан кейін бүкіл роботты бас нүктеге әкелу үшін жалпы позицияны реттеңіз. Бұл процесс бойында компоненттер бірдей әдепкі позицияларда рендерленуі керек.

4. Робот кодынан үлгідегі компоненттер санына сәйкес келетін нөлденген 3D позаларының жиымын жариялаңыз, содан кейін оны AdvantageScope ішінде компонент позаларының жиынтығы ретінде таңдаңыз.

5. Әрбір компонент бас нүктеге теңелгенше оның айналуларын, содан кейін позицияларын реттеңіз. Мысалы, иін (arm) сегменті айналу осі бас нүктеде болып, X осі бойымен алға бағытталып теңестіріледі.

6. Әрбір компонент үшін жаңадан анықталған бас нүктелерге негізделген робот кодынан нақты компонент позаларын жариялаңыз. Мысалы, иін сегментінің позасы сегмент бағытына бағытталған иін буынында орналасады.

## Джойстиктер {#joysticks}

Қалтада «image.webp» атауы бар кескін болуы керек. Конфигурация файлы келесі пішімде болуы керек:

```json
{
  "name": string // Бірегей атау, барлық актив түрлері үшін міндетті
  "components": [...] // Компонент конфигурацияларының жиымы, төменде қараңыз
}
```

:::info
Түймелер, джойстиктер және ось мәндері [SDL](https://www.libsdl.org) байланыстыруларын (қазіргі FIRST Driver Station пайдаланатын) және NI байланыстыруларын (ескі NI FRC Driver Station пайдаланатын) қолдайды. Әрбір компонент үшін кем дегенде бір байланыстырулар жиынтығы берілуі керек.

NI байланыстырулары үшін AdvantageScope ескі префиксіз конфигурация кілттерімен (мысалы, `sourceIndex`) кері үйлесімді. **Қазіргі FIRST Driver Station қолданбасымен үйлесімді болу үшін барлық жаңа джойстиктер айқын SDL байланыстыруларын (мысалы, `sdlSourceIndex`) пайдалануы керек.**
:::

### Жеке түйме / POV мәні {#single-button-pov-value}

```json
{
  "type": "button"
  "isYellow": boolean
  "isEllipse": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number
  "sdlSourcePov": string // Міндетті емес, "up", "right", "down" немесе "left" болуы мүмкін. Егер берілсе, "sdlSourceIndex" оқылатын POV индексі болады.

  // NI Driver Station үшін баламалы байланыстырулар (міндетті емес)
  "niSourceIndex": number
  "niSourcePov": string
}
```

### Екі осьті джойстик {#two-axis-joystick}

```json
{
  "type": "joystick" // Екі өлшемде қозғалатын джойстик
  "isYellow": boolean
  "centerPx": [number, number]
  "radiusPx": number
  "sdlXSourceIndex": number
  "sdlXSourceInverted": boolean // Инверттелмеген: оңға = оң мән
  "sdlYSourceIndex": number
  "sdlYSourceInverted": boolean // Инверттелмеген: жоғары = оң мән
  "sdlButtonSourceIndex": number // Міндетті емес

  // NI Driver Station үшін баламалы байланыстырулар (міндетті емес)
  "niXSourceIndex": number
  "niXSourceInverted": boolean
  "niYSourceIndex": number
  "niYSourceInverted": boolean
  "niButtonSourceIndex": number
}
```

### Жеке ось {#single-axis}

```json
{
  "type": "axis" // Жеке ось мәні
  "isYellow": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number,
  "sdlSourceRange": [number, number] // Инверттеу үшін мин макстан үлкен

  // NI Driver Station үшін баламалы байланыстырулар (міндетті емес)
  "niSourceIndex": number,
  "niSourceRange": [number, number]
}
```

### Тачпад {#touchpad}

```json
{
  "type": "touchpad" // Тачпад
  "isYellow": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number,
}
```

## Тегіс алаң кескіндері {#flat-field-images}

Қалтада «image.webp» атауы бар кескін болуы керек. Ол сол жақта қызыл альянс болатындай бағытталуы тиіс. Конфигурация файлы келесі пішімде болуы керек:

```json
{
  "name": string // Бірегей атау, барлық актив түрлері үшін міндетті
  "isFTC": boolean // Бұл FRC алаңының орнына FTC алаңы ма, жоқ па
  "coordinateSystem": // Пайдаланылатын әдепкі координаттар жүйесі (төменде қараңыз)
      "wall-alliance" |  // FRC 2022
      "wall-blue" |      // FRC 2023-2026
      "center-rotated" | // FTC дәстүрлі
      "center-red"       // Systemcore
  "useGrid": boolean // Егер бұл алаң FTC алаңы болса, тор сызықтарын рендерлеу керек пе, жоқ па (әдепкі "true")
  "sourceUrl": string // Түпнұсқа файлға сілтеме, міндетті емес
  "topLeft": [number, number] // Пиксель координатасы (бас нүкте жоғарғы сол жақта)
  "bottomRight": [number, number] // Пиксель координатасы (бас нүкте жоғарғы сол жақта)
  "widthInches": number // Алаңның нақты ені (ұзын жағы)
  "heightInches": number // Алаңның нақты биіктігі (қысқа жағы)
}
```

## 3D алаң үлгілері {#3d-field-models}

Қалтада «model.glb» атауы бар үлгі болуы керек. Барлық айналулар қолданылғаннан кейін алаң сол жақта қызыл альянс болатындай бағытталуы тиіс. CAD файлдары glTF пішіміне түрлендірілуі тиіс; мәліметтер алу үшін [бұл бетті](gltf-convert) қараңыз. Ойын элементтерінің үлгілері «gamePieces» жиымында пайда болу ретіне қарай «model_INDEX.glb» атау келісімін сақтайды. Осында жарияланған AprilTag тегтері кез келген басқа конфигурация опцияларына қарамастан әрқашан [орталық/қызыл](/more-features/coordinate-systems#center-red) координаттар жүйесін пайдаланып орналастырылады.

Конфигурация файлы келесі пішімде болуы керек:

```json
{
  "name": string // Бірегей атау, барлық актив түрлері үшін міндетті
  "isFTC": boolean // Бұл FRC алаңының орнына FTC алаңы ма, жоқ па
  "coordinateSystem": // Пайдаланылатын әдепкі координаттар жүйесі (төменде қараңыз)
      "wall-alliance" |  // FRC 2022
      "wall-blue" |      // FRC 2023-2026
      "center-rotated" | // FTC дәстүрлі
      "center-red"       // Systemcore
  "useGrid": boolean // Егер бұл алаң FTC алаңы болса, тор сызықтарын рендерлеу керек пе, жоқ па (әдепкі "true")
  "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // x, y және z осьтері бойымен айналу тізбегі
  "widthInches": number // Алаңның нақты ені (ұзын жағы)
  "heightInches": number // Алаңның нақты биіктігі (қысқа жағы)
  "defaultOrigin": "auto" | "blue" | "red" // Әдепкі бас нүкте орны, көрсетілмесе "auto"
```
