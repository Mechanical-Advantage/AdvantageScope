# ⚙️ Пайдаланушы активтері {#custom-assets}

AdvantageScope жазық алаң кескіндерінің, алаң үлгілерінің, робот үлгілерінің және джойстик конфигурацияларының әдепкі жинағын пайдаланады. Қарапайым активтер (мысалы, «Тұрақты» алаңдар) бастапқы орнату құрамына кіреді. Егжей-тегжейлі активтер (мысалы, маусымға арнайы алаңдар) AdvantageScope интернетке қосылған кезде фонда автоматты түрде жүктеп алынады. Осы жүктеп алулардың күйін тексеру үшін `Қолданба`/`AdvantageScope` > `Активтерді жүктеп алу күйі...` тармағын басыңыз.

Қалауыңызша қосымша нұсқаларды қосу үшін активтер жинағын реттеуге болады. Пайдаланушы активтері қалтасын ашу үшін `Қолданба`/`AdvantageScope` > `Активтер қалтасын көрсету` тармағын басыңыз. Активтердің күтілетін пішімдері төменде анықталған. Анықтама ретінде [егжей-тегжейлі активтердің](https://github.com/Mechanical-Advantage/AdvantageScopeAssets/releases) және [жинақталған активтердің](https://github.com/Mechanical-Advantage/AdvantageScope/tree/main/bundledAssets) әдепкі жинағын қараңыз.

:::tip
Активтерді балама орыннан жүктеу үшін `Қолданба`/`AdvantageScope` > `Пайдаланушы активтері қалтасын пайдалану` тармағын басыңыз. Таңдалған қалта бөлек ішкі қалталарда бірнеше активті орналастыруға болатын _аталық қалта_ (parent folder) болуы керек. Бұл мүмкіндік пайдаланушы активтерін робот кодымен бірге нұсқаларды басқару (version control) жүйесінде сақтауға мүмкіндік береді.
:::

## Жалпы пішім {#general-format}

Барлық активтер «TYPE_NAME» атау үлгісіне сай қалталарда сақталады. Қалта атауындағы NAME бөлігі AdvantageScope ішінде көрсетілмейді. Мүмкін болатын актив түрлері:

- "Field2d"
- "Field3d"
- "Robot"
- "Joystick"

:::info
Қалта атауларының мысалдары: «Field2d_2023Field», «Joystick_OperatorButtons» немесе «Robot_Dozer».
:::

Бұл қалтада «config.json» деп аталатын файл және төменде сипатталғандай бір немесе бірнеше актив файлы болуы керек. Конфигурация файлында әрқашан AdvantageScope көрсететін активтің атауы болады. Бұл атау әрбір актив түрі үшін бірегей болуы тиіс. Сондай-ақ активтерде тіл кодтарын (мысалы, «es-419», «fr», «zh-CN») аударылған атаулармен сәйкестендіретін «locales» нысаны болуы мүмкін. Егер таңдалған тіл көрсетілмесе немесе «locales» өткізіп жіберілсе, түбірлік деңгейдегі «name» әдепкі атау ретінде қарастырылады.

```json
{
  "name": string, // Бірегей әдепкі атау, барлық актив түрлері үшін міндетті
  "locales": { [locale: string]: string } // Тіл кодтарын (мысалы, "es-419", "fr") аудармаларға сәйкестендіретін қосымша локализацияланған атаулар
  ... // Түрге байланысты конфигурация, төменде сипатталған
}
```

### Шолу {#overview}

Қалтада «model.glb» атауы бар үлгі болуы керек. CAD файлдары glTF пішіміне түрлендірілуі тиіс; мәліметтер алу үшін [бұл бетті](gltf-convert) қараңыз. Конфигурация файлы келесі пішімде болуы керек:

```json
{
  "name": string // Бірегей атау, барлық актив түрлері үшін міндетті
  "locales": { [locale: string]: string } // Актив атауы үшін қосымша аудармалар
  "isFTC": boolean // Үлгі FRC алаңдарының орнына FTC алаңдарында пайдалануға арналған ба, жоқ па (әдепкі "false")
  "disableSimplification": boolean // Үлгіні оңайлатуды өшіру керек пе, міндетті емес
  "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // x, y және z осьтері бойымен айналу тізбегі
  "position": [number, number, number] // Метрдегі позиция ығысуы, айналудан кейін қолданылады
  "cameras": [ // Бекітілген камера позициялары, бос болуы мүмкін
    {
      "name": string // Камера атауы
      "locales": { [locale: string]: string } // Камера атауы үшін қосымша аудармалар
      "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // x, y және z осьтері бойымен айналу тізбегі
      "position": [number, number, number] // Роботқа қатысты метрдегі позиция ығысуы, айналудан кейін қолданылады
      "resolution": [number, number] // Пиксельдегі ажыратымдылық, бекітілген пропорцияны орнату үшін пайдаланылады
      "fov": number // Градустағы көлденең көру өрісі
    }
  ],
  "components": [...] // «Топсалы компоненттер» бөлімін қараңыз
}
```

Қажетті позиция мен айналу мәндерін анықтаудың ең оңай жолы — байқап көру әдісі. Түрлендірулер осы ретпен қолданылатындықтан, позициядан бұрын айналуды реттеуді ұсынамыз.

:::info
AdvantageScope өнімділікті арттыру үшін үлгі геометриясын автоматты түрде оңайлатады, мұнда егжей-тегжейлілік деңгейі таңдалған [рендеринг режиміне](/tab-reference/3d-field#rendering-modes) байланысты болады. Пайдаланушы активтерінде үлгіні оңайлату қажетсіз нәтиже берген жағдайда екі шешімді пайдалануға болады:

- Белгілі бір тордың (mesh) автоматты түрде жойылуын өшіру үшін оның атауына `NOSIMPLIFY` жолын қосыңыз.
- Бүкіл робот үлгісі үшін үлгіні оңайлатуды өшіру үшін конфигурациядағы `disableSimplification` опциясын `true` күйіне орнатыңыз.

:::

### Топсалы компоненттер {#articulated-components}

:::warning
Топсалы компоненттерді баптау күрделі әрі көп уақыт алуы мүмкін. **3D алаңында механизмдерді визуализациялаудың** неғұрлым ыңғайлы жолы ретінде AdvantageScope қолданбасының 3D [`Mechanism2d` қолдауын](/tab-reference/3d-field#2d-mechanisms) пайдаланып көріңіз.
:::

Робот үлгілерінде механизм деректерін визуализациялауға арналған топсалы компоненттер болуы мүмкін (мәліметтер алу үшін [осы жерді](/tab-reference/3d-field) қараңыз). Негізгі glTF үлгісінде ешқандай компонент болмауы керек, ал әрбір компонент бөлек glTF үлгісі ретінде экспортталуы тиіс. Компонент үлгілері «model_INDEX.glb» атау келісімін сақтайды, сондықтан бірінші топсалы компонент «model_0.glb» болады.

Компонент конфигурациясы роботтың конфигурация файлында беріледі. Компоненттер жиымы «components» кілтінің ішінде көрсетілуі керек. AdvantageScope ішінде пайдаланушы компонент позаларын бермеген кезде, компонент үлгілері роботтың әдепкі айналулары мен позициясы арқылы орналастырылады (жоғарыда қараңыз). Пайдаланушы компонент позаларын берген кезде, әрбір компонентті роботтың координаттар басына келтіру үшін «нөлденген» (zeroed) айналулар мен позиция қолданылады. Содан кейін әрбір компонентті роботтағы тиісті орнына жылжыту үшін пайдаланушы берген позалар қолданылады.

:::tip
3D компоненттерін роботқа қатысты орналастыру кезінде координаттар жүйесінің басы роботтың жарияланған позасына сәйкес келеді. Бұл поза әдетте нөлдік биіктікті пайдаланатынын ескеріңіз; яғни (әдеттегі 2D робот қозғалысында) ол роботтың түбіне (bellypan) емес, еден жазықтығына сәйкес келеді.
:::

```json
"components": [
  {
    "zeroedRotations": { "axis": "x" | "y" | "z", "degrees": number }[] // x, y және z осьтері бойымен айналу тізбегі
    "zeroedPosition": [number, number, number] // Роботқа қатысты метрдегі позиция ығысуы, айналудан кейін қолданылады
  }
]
```

#### Баптау процесі {#setup-process}

Топсалы компоненттердің позицияларын калибрлеу үшін келесі реттілікті ұсынамыз:

1. Негізгі үлгі мен компоненттерді олардың дұрыс «әдепкі» позицияларында экспорттаңыз. AdvantageScope ішінде компонент позалары берілмесе, олар дәл осылай рендерленуі тиіс.

2. Робот кодынан нөлденген 2D позасын жариялап, оны AdvantageScope ішінде робот позасы ретінде таңдаңыз. Алаңның координаттар басын көрсететін «Осьтер» (Axes) 3D алаңына ауысыңыз.

3. Бүкіл робот дұрыс бағытталғанша роботтың жалпы айналуларын (компоненттерді емес) реттеңіз. Содан кейін бүкіл роботты координаттар басына әкелу үшін жалпы позицияны реттеңіз. Бұл процесс барысында компоненттер сол бастапқы әдепкі позицияларында рендерленуі керек.

4. Робот кодынан үлгідегі компоненттер санына сәйкес келетін нөлденген 3D позаларының жиымын жариялап, оны AdvantageScope ішінде компонент позаларының жиынтығы ретінде таңдаңыз.

5. Әрбір компонент координаттар басына теңелгенше оның айналуларын, содан кейін позицияларын реттеңіз. Мысалы, иін (arm) сегментінің топсасы координаттар басына қойылып, өзі X осі бойымен алға қарай бағытталады.

6. Әрбір компонент үшін жаңадан анықталған координаттар басына негізделген нақты компонент позаларын робот кодынан жариялаңыз. Мысалы, иін сегментінің позасы иін буынында орналасып, сегмент бағытына қарай бағытталады.

## Джойстиктер {#joysticks}

Қалтада «image.png» атауы бар кескін болуы керек. Конфигурация файлы келесі пішімде болуы тиіс:

```json
{
  "name": string // Бірегей атау, барлық актив түрлері үшін міндетті
  "locales": { [locale: string]: string } // Актив атауы үшін қосымша аудармалар
  "components": [...] // Компонент конфигурацияларының жиымы, төменде қараңыз
}
```

:::info
Түймелер, джойстиктер және ось мәндері [SDL](https://www.libsdl.org) байланыстыруларын (қазіргі FIRST Driver Station пайдаланатын) және NI байланыстыруларын (ескі NI FRC Driver Station пайдаланатын) қолдайды. Әрбір компонент үшін кемінде бір байланыстыру жиынтығы берілуі керек.

NI байланыстырулары үшін AdvantageScope ескі префиксіз конфигурация кілттерімен (мысалы, `sourceIndex`) кері үйлесімді. **Қазіргі FIRST Driver Station қолданбасымен үйлесімді болу үшін барлық жаңа джойстиктер айқын SDL байланыстыруларын (мысалы, `sdlSourceIndex`) пайдалануы керек.**
:::

### Жеке түйме / POV мәні {#single-button-pov-value}

```json
{
  "type": "button"
  "isYellow": boolean
  "isEllipse": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number
  "sdlSourcePov": string // Міндетті емес, "up", "right", "down" немесе "left" болуы мүмкін. Егер берілсе, "sdlSourceIndex" оқылатын POV индексі болады.

  // NI Driver Station үшін балама байланыстырулар (міндетті емес)
  "niSourceIndex": number
  "niSourcePov": string
}
```

### Екі осьті джойстик {#two-axis-joystick}

```json
{
  "type": "joystick" // Екі өлшемде қозғалатын джойстик
  "isYellow": boolean
  "centerPx": [number, number]
  "radiusPx": number
  "sdlXSourceIndex": number
  "sdlXSourceInverted": boolean // Инверттелмеген: оңға = оң мән
  "sdlYSourceIndex": number
  "sdlYSourceInverted": boolean // Инверттелмеген: жоғары = оң мән
  "sdlButtonSourceIndex": number // Міндетті емес

  // NI Driver Station үшін балама байланыстырулар (міндетті емес)
  "niXSourceIndex": number
  "niXSourceInverted": boolean
  "niYSourceIndex": number
  "niYSourceInverted": boolean
  "niButtonSourceIndex": number
}
```

## Жазық алаң кескіндері {#flat-field-images}

Қалтада «image.png» атауы бар кескін болуы керек. Ол сол жақта қызыл альянс болатындай бағытталуы тиіс. Конфигурация файлы келесі пішімде болуы керек:

```json
{
  "name": string // Бірегей атау, барлық актив түрлері үшін міндетті
  "locales": { [locale: string]: string } // Актив атауы үшін қосымша аудармалар
  "isFTC": boolean // Бұл FRC алаңының орнына FTC алаңы ма, жоқ па
  "coordinateSystem": // Пайдаланылатын әдепкі координаттар жүйесі (төменде қараңыз)
      "wall-alliance" |  // FRC 2022
      "wall-blue" |      // FRC 2023-2026
      "center-rotated" | // FTC дәстүрлі
      "center-red"       // Systemcore
  "useGrid": boolean // Егер бұл алаң FTC алаңы болса, тор сызықтарын рендерлеу керек пе, жоқ па (әдепкі "true")
  "sourceUrl": string // Түпнұсқа файлға сілтеме, міндетті емес
  "topLeft": [number, number] // Пиксель координатасы (координаттар басы жоғарғы сол жақта)
  "bottomRight": [number, number] // Пиксель координатасы (координаттар басы жоғарғы сол жақта)
  "widthInches": number // Алаңның нақты ені (ұзын жағы)
  "heightInches": number // Алаңның нақты биіктігі (қысқа жағы)
}
```

## 3D алаң үлгілері {#3d-field-models}

Қалтада «model.glb» атауы бар үлгі болуы керек. Барлық айналу қолданылғаннан кейін алаң сол жақта қызыл альянс болатындай бағытталуы тиіс. CAD файлдары glTF пішіміне түрлендірілуі тиіс; мәліметтер алу үшін [бұл бетті](gltf-convert) қараңыз. Ойын элементтерінің үлгілері «gamePieces» жиымында пайда болу ретіне қарай «model_INDEX.glb» атау келісімін сақтайды. Осында жарияланған AprilTag тегтері кез келген басқа конфигурация опцияларына қарамастан әрқашан [орталық/қызыл](/more-features/coordinate-systems#center-red) координаттар жүйесін пайдаланып орналастырылады.

Конфигурация файлы келесі пішімде болуы керек:

```json
{
```
