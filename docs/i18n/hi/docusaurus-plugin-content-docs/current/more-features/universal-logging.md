# 🪐 WPILOG के साथ यूनिवर्सल लॉगिंग {#universal-logging-with-wpilog}

WPILOG पूरे WPILib इकोसिस्टम में उपयोग किया जाने वाला मानक ओपन लॉगिंग फ़ॉर्मेट है। AdvantageScope के साथ, WPILOG कई लॉग फ़ाइलों और फ़ॉर्मेट्स के लिए एक यूनिवर्सल कंटेनर के रूप में कार्य कर सकता है। इसका मतलब है कि एक ही `.wpilog` फ़ाइल में AdvantageScope द्वारा समर्थित किसी भी फ़ॉर्मेट (जैसे CSV, वेंडर-विशिष्ट लॉग, या अतिरिक्त WPILOG फ़ाइलें) में एन्कोडेड कई डेटा स्ट्रीम्स हो सकते हैं।

यह फ़ीचर **रोबोट के सभी डायग्नोस्टिक डेटा को एक ही यूनिवर्सल लॉग फ़ाइल में एकत्र करके** डायग्नोस्टिक्स को सरल बनाने के लिए डिज़ाइन किया गया है; थर्ड-पार्टी लाइब्रेरी या बाहरी सेवाओं से डेटा एकत्र करते समय भी एक ही मैच से कई लॉग फ़ाइलें डाउनलोड करने, जोड़ने या सिंक्रनाइज़ करने की कोई आवश्यकता नहीं है। उदाहरण के लिए, एकल WPILOG फ़ाइल में ये शामिल हो सकते हैं:

- WPILib के `Telemetry` API या NetworkTables के माध्यम से पब्लिश की गई मानक रोबोट टेलीमेट्री।
- वेंडर लाइब्रेरी द्वारा लॉग किए गए उच्च-आवृत्ति डिवाइस सिग्नल।
- CSV या WPILOG में लॉग किए गए कोप्रोसेसर और बाहरी सेवाओं का स्टेटस डेटा।
- ...और भी बहुत कुछ!

यह सारा डेटा AdvantageScope में एक ही एकीकृत ट्री में दिखाई देता है, जैसा कि नीचे कई वेंडर्स द्वारा कैप्चर किए गए डिवाइस सिग्नल्स वाली एक WPILOG फ़ाइल में दिखाया गया है।

:::note
Systemcore पर, [URCL](https://github.com/Mechanical-Advantage/URCL) को आधिकारिक REV [स्टेटस लॉगर](https://docs.revrobotics.com/revlib/logs) द्वारा बदल दिया गया है। AdvantageScope के साथ यूनिवर्सल लॉगिंग आधिकारिक स्टेटस लॉगर को सभी REV डिवाइस से डेटा को एक ही WPILOG फ़ाइल में रिकॉर्ड करने की अनुमति देता है (URCL के समान)।
:::

AdvantageKit उपयोगकर्ता WPILOG के भीतर संग्रहीत थर्ड-पार्टी लॉग के आकार को काफी कम करने के लिए XZ कम्प्रेशन का भी लाभ उठा सकते हैं। विवरण के लिए लॉग डेटा रिसीवर्स पर AdvantageKit डॉक्यूमेंटेशन देखें।
:::

## प्रायोगिक: वेंडर लॉगिंग {#experimental-vendor-logging}

कई रोबोट प्रोजेक्ट एक साथ कई लॉग फ़ाइलें बनाते हैं: WPILib/AdvantageKit टेलीमेट्री के लिए एक मानक WPILOG फ़ाइल और वेंडर लाइब्रेरी से मालिकाना फ़ाइलें। यूनिवर्सल लॉगिंग इन वेंडर लॉग्स को सीधे मुख्य `.wpilog` में एम्बेड करके इस विभाजन को समाप्त करता है। WPILib और AdvantageKit के लिए नीचे दिए गए निर्देश देखें।

:::warning
चूंकि यह दृष्टिकोण वेंडर्स द्वारा आधिकारिक रूप से समर्थित नहीं है, इसलिए सहायता अनुरोध AdvantageScope के [इश्यूज़ पेज](https://github.com/Mechanical-Advantage/AdvantageScope/issues) या software@team6328.org पर भेजे जाने चाहिए। डायग्नोस्टिक्स के लिए मूल लॉग फ़ाइलें एक्सपोर्ट करने के विवरण के लिए [वेंडर डेटा एक्सपोर्ट करना](#exporting-vendor-data) देखें।
:::

```java
public Robot() {
  // WPILib का DataLogManager सामान्य रूप से शुरू करें
  DataLogManager.start();

  // अस्थायी स्टेजिंग डायरेक्टरी से वेंडर लॉग कैप्चर करना सक्षम करें
  // USB ड्राइव का उपयोग करते समय भी हम वेंडर लॉग्स को आंतरिक स्टोरेज पर
  // स्टेज करने की अनुशंसा करते हैं (कैप्चर के बाद वेंडर लॉग्स स्थायी नहीं रहते)
  VendorLogCapture.start(DataLogManager.getLog(), "/home/systemcore/logs/");

  // लॉग कैप्चर सक्षम होने के बाद वेंडर लॉगर शुरू करें
  // यदि कॉन्फ़िगर करने योग्य हो, तो आउटपुट डायरेक्टरी उपरोक्त पथ से मेल खानी चाहिए
  VendorLogger.setPath("/home/systemcore/logs/");
  VendorLogger.start();
}
```

ध्यान दें कि कुछ वेंडर लॉगर संबंधित डिवाइस क्लास (जैसे `SparkMax`) के इंस्टैंशिएट होते ही _तुरंत_ डेटा लिखना शुरू कर देते हैं। यह सुनिश्चित करने के लिए कि लॉग कैप्चर हों, हम `Robot` कंस्ट्रक्टर के अंत तक हार्डवेयर ऑब्जेक्ट्स को इंस्टैंशिएट करने की प्रतीक्षा करने की अनुशंसा करते हैं।

### यह कैसे काम करता है {#how-it-works}

1. **कैप्चर:** रोबोट प्रोग्राम वेंडर लॉगर्स के साथ मानक WPILib लॉगिंग चलाता है। एक हल्का हेल्पर समय-समय पर वेंडर लॉगर्स द्वारा लिखे गए नए डेटा को पढ़ता है और कच्चे चंक्स को सीधे सक्रिय `DataLog` स्ट्रीम में पैकेज करता है।
2. **स्टोरेज:** पूरी संयुक्त लॉग फ़ाइल एक ही `.wpilog` फ़ाइल में सहेजी जाती है (उदाहरण के लिए Systemcore से जुड़े USB फ्लैश ड्राइव पर)। रोबोट पर बनी अस्थायी वेंडर लॉग फ़ाइलें रीबूट के बाद नहीं रहतीं, जिससे स्टोरेज भरने से बचता है।
3. **विज़ुअलाइज़ेशन:** जब AdvantageScope `.wpilog` खोलता है, तो वह स्वचालित रूप से किसी भी एम्बेडेड लॉग प्रविष्टि को खोजता है, उनकी सामग्री को डिकोड करता है, और मानक टेलीमेट्री के साथ सभी फ़ील्ड्स को साइडबार ट्री में मर्ज कर देता है।
4. **निष्कर्षण:** यदि आपको सहायता या उन्नत डायग्नोस्टिक्स के लिए वेंडर लॉग खोलने की आवश्यकता है, तो [वेंडर डेटा एक्सपोर्ट करना](#exporting-vendor-data) में बताए गए अनुसार `.wpilog` से मूल वेंडर लॉग फ़ाइलें बिना किसी डेटा हानि के निकाली जा सकती हैं।

बाहरी लॉग डेटा को एक कच्ची प्रविष्टि का उपयोग करके WPILOG फ़ॉर्मेट में सहेजा जाता है जिसका टाइप स्ट्रिंग `log:<format>` परंपरा का पालन करता है। इनमें से किसी एक फ़ील्ड को पार्स करते समय, AdvantageScope कालानुक्रमिक क्रम में उस प्रविष्टि के सभी बाइनरी रिकॉर्ड्स को जोड़ता है और परिणामी पेलोड को निर्दिष्ट फ़ॉर्मेट में एक स्टैंडअलोन लॉग के रूप में डिकोड करता है। फिर डिकोड किए गए सिग्नल्स को मुख्य फ़ील्ड ट्री में मर्ज किया जाता है और मौजूदा डेटा के साथ स्वचालित रूप से सिंक्रनाइज़ किया जाता है।

:::tip
WPILOG के साथ यूनिवर्सल लॉगिंग केवल वेंडर लॉग्स तक सीमित नहीं है; उसी परंपरा का उपयोग करके AdvantageScope के साथ संगत किसी भी लॉगिंग फ़ॉर्मेट को WPILOG में एम्बेड किया जा सकता है।
:::

### वेंडर डेटा एक्सपोर्ट करना {#exporting-vendor-data}

यद्यपि वेंडर लॉग्स के डेटा को सीधे AdvantageScope में ब्राउज़ किया जा सकता है, कभी-कभी मूल वेंडर लॉग को उसी रूप में निकालना आवश्यक हो सकता है जैसा वह मूल लाइब्रेरी द्वारा बनाया गया था (उदाहरण के लिए वेंडर-विशिष्ट यूटिलिटीज़ में निरीक्षण के लिए)।

सीधे AdvantageScope से किसी व्यक्तिगत चाइल्ड लॉग को एक्सपोर्ट करने के लिए, साइडबार में चाइल्ड लॉग प्रविष्टि पर दायाँ-क्लिक करें और **मूल लॉग एक्सपोर्ट करें...** चुनें।

बैच निष्कर्षण के लिए, आप [`extract_vendor_logs.py`](https://github.com/Mechanical-Advantage/AdvantageScope/blob/main/docs/snippets/extract_vendor_logs.py) Python स्क्रिप्ट का भी उपयोग कर सकते हैं, जो सभी एकीकृत वेंडर लॉग्स के लिए एक या अधिक `.wpilog` या `.wpilogxz` फ़ाइलों को खोजती है और उन्हें अलग-अलग फ़ाइलों में एक्सपोर्ट करती है:

```bash
pip3 install robotpy-wpiutil # आवश्यक निर्भरता
python3 extract_vendor_logs.py path/to/source.wpilog
```
