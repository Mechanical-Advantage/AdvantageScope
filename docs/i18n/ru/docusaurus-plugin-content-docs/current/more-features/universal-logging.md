# 🪐 Универсальное логирование с WPILOG

WPILOG — это стандартный открытый формат логирования, используемый во всей экосистеме WPILib. С помощью AdvantageScope формат WPILOG может служить универсальным контейнером для нескольких файлов и форматов логов. Это означает, что один файл `.wpilog` может содержать несколько потоков данных, закодированных в любом формате, поддерживаемом AdvantageScope, включая CSV, логи производителей или дополнительные файлы WPILOG.

Эта функция предназначена для упрощения диагностики за счёт сбора **всех диагностических данных робота в одном универсальном файле лога**: больше не нужно скачивать, связывать или синхронизировать несколько файлов логов за один матч, даже при сборе данных из сторонних библиотек или внешних сервисов. Например, один файл WPILOG может содержать:

- Стандартную телеметрию робота, публикуемую через API `Telemetry` из WPILib или NetworkTables.
- Высокочастотные сигналы устройств, записываемые библиотеками производителей.
- Данные о состоянии сопроцессоров и внешних сервисов, записанные в CSV или WPILOG.
- ...и многое другое!

Все эти данные отображаются в едином общем дереве в AdvantageScope, как показано ниже на примере файла WPILOG, содержащего сигналы устройств от нескольких производителей.

:::note
На Systemcore библиотека [URCL](https://github.com/Mechanical-Advantage/URCL) была заменена официальным [логгером состояния](https://docs.revrobotics.com/revlib/logs) от REV. Универсальное логирование в AdvantageScope позволяет официальному логгеру состояния записывать данные со всех устройств REV в один файл WPILOG (аналогично URCL).
:::

## Экспериментально: логирование производителей {#experimental-vendor-logging}

Многие проекты роботов одновременно создают несколько файлов логов: стандартный файл WPILOG для телеметрии WPILib/AdvantageKit наряду с проприетарными файлами от библиотек производителей. Универсальное логирование устраняет это разделение, встраивая такие логи производителей непосредственно в основной файл `.wpilog`. Смотрите инструкции ниже для WPILib и AdvantageKit.

:::note
Поскольку этот подход официально не поддерживается производителями, запросы в поддержку следует направлять на [страницу Issues](https://github.com/Mechanical-Advantage/AdvantageScope/issues) AdvantageScope или на адрес software@team6328.org. Подробности об экспорте исходных файлов логов для диагностики смотрите в разделе [Экспорт данных производителей](#exporting-vendor-data).
:::

Обратите внимание, что некоторые логгеры производителей начинают записывать данные _немедленно_ при создании экземпляра соответствующего класса устройства (например, `SparkMax`). Мы рекомендуем отложить создание объектов оборудования до конца конструктора `Robot`, чтобы гарантировать захват логов.

### Как это работает {#how-it-works}

1. **Захват:** Программа робота запускает стандартное логирование WPILib вместе с логгерами производителей. Лёгкий вспомогательный модуль периодически считывает новые данные, записанные логгерами производителей, и упаковывает необработанные фрагменты непосредственно в активный поток `DataLog`.
2. **Хранение:** Весь объединённый лог сохраняется в один файл `.wpilog` (например, на USB-накопителе, подключённом к Systemcore). Временные файлы логов производителей, созданные на роботе, не сохраняются после перезагрузки, что предотвращает переполнение памяти.
3. **Визуализация:** Когда AdvantageScope открывает `.wpilog`, он автоматически обнаруживает все встроенные записи логов, декодирует их содержимое и объединяет все поля в дерево на боковой панели наряду со стандартной телеметрией.
4. **Извлечение:** Если Вам нужно открыть лог производителя для обращения в поддержку или углублённой диагностики, исходные файлы логов производителей можно извлечь без потерь из `.wpilog`, как описано в разделе [Экспорт данных производителей](#exporting-vendor-data).

Внешние данные логов сохраняются в формате WPILOG с использованием необработанной записи, строка типа которой соответствует соглашению `log:<format>`. При разборе одного из таких полей AdvantageScope объединяет все двоичные записи для этой записи в хронологическом порядке и декодирует полученную полезную нагрузку как отдельный лог в указанном формате. Декодированные сигналы затем объединяются в основное дерево полей и автоматически синхронизируются с существующими данными.

:::tip
Универсальное логирование с WPILOG не ограничивается логами производителей; любой формат логирования, совместимый с AdvantageScope, может быть встроен в WPILOG с использованием того же соглашения.
:::

### Экспорт данных производителей {#exporting-vendor-data}

Хотя данные из логов производителей можно просматривать непосредственно в AdvantageScope, иногда может потребоваться извлечь исходный лог в том виде, в котором он был создан исходной библиотекой (например, для проверки в специализированных утилитах производителя).

Чтобы экспортировать отдельный дочерний лог непосредственно из AdvantageScope, нажмите правой кнопкой мыши на запись дочернего лога на боковой панели и выберите **Экспортировать исходный лог...**.

Для пакетного извлечения Вы также можете использовать Python-скрипт [`extract_vendor_logs.py`](https://github.com/Mechanical-Advantage/AdvantageScope/blob/main/docs/snippets/extract_vendor_logs.py), который ищет в одном или нескольких файлах `.wpilog` или `.wpilogxz` все встроенные логи производителей и экспортирует их в отдельные файлы:

```bash
pip3 install robotpy-wpiutil # Необходимая зависимость
python3 extract_vendor_logs.py path/to/source.wpilog
```
