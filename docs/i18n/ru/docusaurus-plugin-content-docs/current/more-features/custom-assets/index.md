# ⚙️ Пользовательские ресурсы {#custom-assets}

AdvantageScope использует набор по умолчанию плоских изображений полей, моделей полей, моделей роботов и конфигураций джойстиков. Простые ресурсы (например, универсальные поля "evergreen") включены в первоначальную установку. Подробные ресурсы (например, поля для конкретных сезонов) скачиваются автоматически в фоновом режиме, когда AdvantageScope подключен к интернету. Чтобы проверить статус этих скачиваний, нажмите `Приложение`/`AdvantageScope` > `Статус загрузки ресурсов...`.

Набор ресурсов можно настроить для добавления дополнительных опций при желании. Чтобы открыть пользовательскую папку ресурсов, нажмите `Приложение`/`AdvantageScope` > `Показать папку ресурсов`. Ожидаемые форматы для ресурсов определены ниже. Смотрите наборы по умолчанию [подробных ресурсов](https://github.com/Mechanical-Advantage/AdvantageScopeAssets/releases) и [встроенных ресурсов](https://github.com/Mechanical-Advantage/AdvantageScope/tree/main/bundledAssets) для справки.

:::tip
Чтобы загружать ресурсы из альтернативного места, нажмите `Приложение`/`AdvantageScope` > `Использовать пользовательскую папку ресурсов`. Выбранная папка должна быть _родительской папкой_, где можно разместить несколько ресурсов в отдельных подпапках. Эта функция позволяет хранить пользовательские ресурсы под контролем версий вместе с кодом робота.
:::

## Общий формат {#general-format}

Все ресурсы хранятся в папках с соглашением об именовании «ТИП_ИМЯ». ИМЯ, используемое для папки, не отображается в AdvantageScope. Возможные типы ресурсов:

- "Field2d"
- "Field3d"
- "Robot"
- "Joystick"

:::info
Примерами имен папок могут быть "Field2d_2023Field", "Joystick_OperatorButtons" или "Robot_Dozer".
:::

Эта папка должна содержать файл с именем "config.json" и один или несколько файлов ресурсов, как описано ниже. Конфигурационный файл всегда включает имя ресурса для отображения в AdvantageScope. Это имя должно быть уникальным для каждого типа ресурса.

```json
{
  "name": string // Уникальное имя, требуется для всех типов ресурсов
  ... // Конфигурация, зависящая от типа, описана ниже
}
```

### Обзор {#overview}

Модель должна быть включена в папку с именем "model.glb". Файлы CAD должны быть преобразованы в glTF; смотрите [эту страницу](gltf-convert) для получения подробностей. Конфигурационный файл должен быть в следующем формате:

```json
{
  "name": string // Уникальное имя, требуется для всех типов ресурсов
  "isFTC": boolean // Предназначена ли модель для использования на полях FTC вместо полей FRC (по умолчанию "false")
  "disableSimplification": boolean // Отключить ли упрощение модели, необязательно
  "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
  "position": [number, number, number] // Смещение позиции в метрах, применяемое после вращения
  "cameras": [ // Фиксированные позиции камер, может быть пустым
    {
      "name": string // Имя камеры
      "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
      "position": [number, number, number] // Смещение позиции в метрах относительно робота, применяемое после вращения
      "resolution": [number, number] // Разрешение в пикселях, используемое для задания фиксированного соотношения сторон
      "fov": number // Горизонтальное поле зрения в градусах
    }
  ],
  "components": [...] // См. "Артикулированные компоненты"
}
```

Самый простой способ определить подходящие значения позиции и вращения — путем проб и ошибок. Мы рекомендуем настраивать вращение перед позицией, так как преобразования применяются в этом порядке.

:::info
AdvantageScope автоматически упрощает геометрию модели для повышения производительности, где уровень детализации зависит от выбранного [режима рендеринга](/tab-reference/3d-field#rendering-modes). В случаях, когда упрощение модели приводит к нежелательным эффектам с пользовательскими ресурсами, можно использовать два решения:

- Чтобы отключить автоматическое удаление конкретной меш-сетки, включите строку `NOSIMPLIFY` в имя меш-сетки.
- Чтобы отключить упрощение модели для всей модели робота, установите опцию `disableSimplification` в конфигурации в `true`.

:::

### Артикулированные компоненты {#articulated-components}

:::warning
Настройка артикулированных компонентов может быть сложной и отнимать много времени. Рассмотрите возможность использования поддержки [2D-`Mechanism2d` в 3D](/tab-reference/3d-field#2d-mechanisms) в AdvantageScope, которая предлагает более простой подход к **визуализации механизмов на 3D-поле**.
:::

Модели роботов могут содержать артикулированные компоненты для визуализации данных механизмов (см. [здесь](/tab-reference/3d-field) для получения подробностей). Базовая модель glTF не должна содержать компонентов, затем каждый компонент должен быть экспортирован как отдельная модель glTF. Модели компонентов следуют соглашению об именовании "model_ИНДЕКС.glb", поэтому первым артикулированным компонентом будет "model_0.glb"

Конфигурация компонентов предоставляется в конфигурационном файле робота. Массив компонентов должен предоставляться под ключом "components". Когда пользователем в AdvantageScope не предоставлены позы компонентов, модели компонентов будут позиционироваться с использованием вращений и позиции робота по умолчанию (см. выше). Когда позы компонентов предоставляются пользователем, к каждому компоненту применяются «обнуленные» вращения и позиция, чтобы привести его к началу координат робота. Затем применяются позы пользователя, чтобы переместить каждый компонент в правильное место на роботе.

:::tip
При позиционировании 3D-компонентов относительно робота начало системы координат совпадает с опубликованной позой робота. Обратите внимание, что эта поза обычно использует нулевую высоту, то есть плоскость пола, а НЕ днище робота (для типичного 2D-движения робота).
:::

```json
"components": [
  {
    "zeroedRotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
    "zeroedPosition": [number, number, number] // Смещение позиции в метрах относительно робота, применяемое после вращения
  }
]
```

#### Процесс настройки {#setup-process}

Для калибровки позиций артикулированных компонентов мы рекомендуем следующий процесс:

1. Экспортируйте базовую модель и компоненты в их правильных позициях «по умолчанию». Так они должны рендериться, если позы компонентов не предоставлены в AdvantageScope.

2. Опубликуйте обнуленную 2D-позу из кода робота, затем выберите ее в качестве позы робота в AdvantageScope. Переключитесь на 3D-поле «Оси», которое показывает начало координат поля.

3. Настраивайте общие вращения робота (не компонентов), пока весь робот не будет ориентирован правильно. Затем настройте общую позицию, чтобы привести всего робота к началу координат. Компоненты должны рендериться в тех же позициях по умолчанию на протяжении всего этого процесса.

4. Опубликуйте массив обнуленных 3D-поз из кода робота, соответствующий количеству компонентов в модели, затем выберите его в качестве набора поз компонентов в AdvantageScope.

5. Настройте вращения, а затем позиции для каждого компонента, пока они не будут выровнены по началу координат. Например, сегмент рычага будет выровнен так, чтобы поворот находился в начале координат и был направлен вперед вдоль оси X.

6. Опубликуйте реальные позы компонентов из кода робота, которые будут основаны на вновь определенных началах координат для каждого компонента. Например, поза для сегмента рычага будет позиционирована в шарнире рычага, направленном в сторону сегмента.

## Джойстики {#joysticks}

Изображение должно быть включено в папку с именем "image.webp". Конфигурационный файл должен быть в следующем формате:

```json
{
  "name": string // Уникальное имя, требуется для всех типов ресурсов
  "components": [...] // Массив конфигураций компонентов, см. ниже
}
```

:::info
Кнопки, джойстики и значения осей поддерживают привязки [SDL](https://www.libsdl.org) (используемые текущим FIRST Driver Station) и привязки NI (используемые старым NI FRC Driver Station). Для каждого компонента должен быть предоставлен хотя бы один набор привязок.

Для привязок NI AdvantageScope обратно совместим со старыми ключами конфигурации без префиксов (например, `sourceIndex`). **Все новые джойстики должны использовать явные привязки SDL (например, `sdlSourceIndex`) для совместимости с текущим FIRST Driver Station.**
:::

### Одиночная кнопка / значение POV {#single-button-pov-value}

```json
{
  "type": "button"
  "isYellow": boolean
  "isEllipse": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number
  "sdlSourcePov": string // Необязательно, может быть "up", "right", "down" или "left". Если предоставлено, "sdlSourceIndex" будет индексом POV для чтения.

  // Альтернативные привязки для NI Driver Station (необязательно)
  "niSourceIndex": number
  "niSourcePov": string
}
```

### Двухосевой джойстик {#two-axis-joystick}

```json
{
  "type": "joystick" // Джойстик, перемещающийся в двух измерениях
  "isYellow": boolean
  "centerPx": [number, number]
  "radiusPx": number
  "sdlXSourceIndex": number
  "sdlXSourceInverted": boolean // Не инвертировано: вправо = положительное
  "sdlYSourceIndex": number
  "sdlYSourceInverted": boolean // Не инвертировано: вверх = положительное
  "sdlButtonSourceIndex": number // Необязательно

  // Альтернативные привязки для NI Driver Station (необязательно)
  "niXSourceIndex": number
  "niXSourceInverted": boolean
  "niYSourceIndex": number
  "niYSourceInverted": boolean
  "niButtonSourceIndex": number
}
```

### Одиночная ось {#single-axis}

```json
{
  "type": "axis" // Значение одной оси
  "isYellow": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number,
  "sdlSourceRange": [number, number] // Мин больше макс для инвертирования

  // Альтернативные привязки для NI Driver Station (необязательно)
  "niSourceIndex": number,
  "niSourceRange": [number, number]
}
```

### Тачпад {#touchpad}

```json
{
  "type": "touchpad" // Тачпад
  "isYellow": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number,
}
```

## Плоские изображения полей {#flat-field-images}

Изображение должно быть включено в папку с именем "image.webp". Оно должно быть ориентировано с красным альянсом слева. Конфигурационный файл должен быть в следующем формате:

```json
{
  "name": string // Уникальное имя, требуется для всех типов ресурсов
  "isFTC": boolean // Является ли это полем FTC вместо поля FRC
  "coordinateSystem": // Система координат по умолчанию для использования (см. ниже)
      "wall-alliance" |  // FRC 2022
      "wall-blue" |      // FRC 2023-2026
      "center-rotated" | // FTC традиционная
      "center-red"       // Systemcore
  "useGrid": boolean // Отображать ли линии сетки, если это поле FTC (по умолчанию "true")
  "sourceUrl": string // Ссылка на оригинальный файл, необязательно
  "topLeft": [number, number] // Пиксельная координата (начало в верхнем левом углу)
  "bottomRight": [number, number] // Пиксельная координата (начало в верхнем левом углу)
  "widthInches": number // Реальная ширина поля (длинная сторона)
  "heightInches": number // Реальная высота поля (короткая сторона)
}
```

## 3D-модели полей {#3d-field-models}

Модель должна быть включена в папку с именем "model.glb". После применения всех вращений поле должно быть ориентировано с красным альянсом слева. Файлы CAD должны быть преобразованы в glTF; смотрите [эту страницу](gltf-convert) для получения подробностей. Модели игровых элементов следуют соглашению об именовании "model_ИНДЕКС.glb" на основе порядка их появления в массиве "gamePieces". Объявленные здесь AprilTag всегда позиционируются с использованием системы координат [центр/красные](/more-features/coordinate-systems#center-red), независимо от любых других параметров конфигурации.

Конфигурационный файл должен быть в следующем формате:

```json
{
  "name": string // Уникальное имя, требуется для всех типов ресурсов
  "isFTC": boolean // Является ли это полем FTC вместо поля FRC
  "coordinateSystem": // Система координат по умолчанию для использования (см. ниже)
      "wall-alliance" |  // FRC 2022
      "wall-blue" |      // FRC 2023-2026
      "center-rotated" | // FTC традиционная
      "center-red"       // Systemcore
  "useGrid": boolean // Отображать ли линии сетки, если это поле FTC (по умолчанию "true")
  "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
  "widthInches": number // Реальная ширина поля (длинная сторона)
  "heightInches": number // Реальная высота поля (короткая сторона)
  "defaultOrigin": "auto" | "blue" | "red" // Местоположение начала координат по умолчанию, "auto", если не указано
  "driverStations": [
    [number, number] // Позиции станций управления (X и Y в метрах относительно центра поля)
    ...              // Для FRC 6 элементов в порядке [B1, B2, B3, R1, R2, R3]. Для FTC 4 элемента в порядке [BL, BR, RL, RR].
  ]
  "gamePieces": [ // Список типов игровых элементов
    {
      "name": string // Имя игрового элемента
      "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
      "position": [number, number, number] // Смещение позиции в метрах, применяемое после вращения
      "stagedObjects": string[] // Имена размещенных объектов игровых элементов для скрытия при наличии поз пользователя
    },
    ...
  ],
  "aprilTags": [ // Список дополнительных моделей AprilTag (если не являются частью модели поля)
    "variant": string // Формат "FAMILY-SIZEin", где "FAMILY" — это "36h11" или "16h5", а "SIZE" — длина черной секции
    "id": number
    "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
    "position": [number, number, number] // Смещение позиции в метрах, применяемое после вращения
  ]
}
```
