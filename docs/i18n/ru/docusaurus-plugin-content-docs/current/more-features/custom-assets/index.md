# ⚙️ Пользовательские ресурсы {#custom-assets}

AdvantageScope использует стандартный набор плоских изображений полей, моделей полей, моделей роботов и конфигураций джойстиков. Простые ресурсы (например, универсальные поля «evergreen») включены в первоначальную установку. Подробные ресурсы (например, поля для конкретных сезонов) скачиваются автоматически в фоновом режиме, когда AdvantageScope подключён к интернету. Чтобы проверить статус этих скачиваний, нажмите `Приложение`/`AdvantageScope` > `Статус загрузки ресурсов...`.

При желании набор ресурсов можно расширить. Чтобы открыть пользовательскую папку ресурсов, нажмите `Приложение`/`AdvantageScope` > `Показать папку ресурсов`. Ожидаемые форматы ресурсов описаны ниже. Для справки ознакомьтесь со стандартными наборами [подробных ресурсов](https://github.com/Mechanical-Advantage/AdvantageScopeAssets/releases) и [встроенных ресурсов](https://github.com/Mechanical-Advantage/AdvantageScope/tree/main/bundledAssets).

:::tip
Чтобы загружать ресурсы из альтернативного места, нажмите `Приложение`/`AdvantageScope` > `Использовать пользовательскую папку ресурсов`. Выбранная папка должна быть _родительской папкой_, в которой несколько ресурсов размещены в отдельных подпапках. Эта функция позволяет хранить пользовательские ресурсы под контролем версий вместе с кодом робота.
:::

## Общий формат {#general-format}

Все ресурсы хранятся в папках с именами вида «ТИП_ИМЯ». ИМЯ, используемое в названии папки, не отображается в AdvantageScope. Возможные типы ресурсов:

- «Field2d»
- «Field3d»
- «Robot»
- «Joystick»

:::info
Примеры имён папок: «Field2d_2023Field», «Joystick_OperatorButtons» или «Robot_Dozer».
:::

Эта папка должна содержать файл «config.json» и один или несколько файлов ресурсов, как описано ниже. Конфигурационный файл всегда включает имя ресурса для отображения в AdvantageScope; это имя должно быть уникальным для каждого типа ресурса. Ресурсы также могут содержать необязательный объект «locales», сопоставляющий коды языков (например, «en-US», «es-419», «fr») с переведёнными названиями. Значение «name» на корневом уровне используется как имя по умолчанию, если выбранный язык не указан или объект «locales» отсутствует.

```json
{
  "name": string, // Уникальное имя по умолчанию, требуется для всех типов ресурсов
  "locales": { [locale: string]: string } // Необязательные локализованные имена, сопоставляющие коды языков (например, "en-US", "fr") с переводами
  ... // Конфигурация, зависящая от типа, описана ниже
}
```

### Обзор {#overview}

Модель должна находиться в папке под именем «model.glb». Файлы CAD необходимо преобразовать в glTF; подробности см. на [этой странице](gltf-convert). Конфигурационный файл должен иметь следующий формат:

```json
{
  "name": string // Уникальное имя, требуется для всех типов ресурсов
  "locales": { [locale: string]: string } // Необязательные переводы для имени ресурса
  "isFTC": boolean // Предназначена ли модель для использования на полях FTC вместо полей FRC (по умолчанию "false")
  "disableSimplification": boolean // Отключить ли упрощение модели, необязательно
  "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
  "position": [number, number, number] // Смещение позиции в метрах, применяемое после вращения
  "cameras": [ // Фиксированные позиции камер, может быть пустым
    {
      "name": string // Имя камеры
      "locales": { [locale: string]: string } // Необязательные переводы для имени камеры
      "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
      "position": [number, number, number] // Смещение позиции в метрах относительно робота, применяемое после вращения
      "resolution": [number, number] // Разрешение в пикселях, используемое для задания фиксированного соотношения сторон
      "fov": number // Горизонтальное поле зрения в градусах
    }
  ],
  "components": [...] // См. «Подвижные компоненты»
}
```

Самый простой способ подобрать подходящие значения позиции и вращения — методом проб и ошибок. Мы рекомендуем настраивать вращение перед позицией, так как преобразования применяются именно в этом порядке.

:::info
AdvantageScope автоматически упрощает геометрию модели для повышения производительности, причём уровень детализации зависит от выбранного [режима рендеринга](/tab-reference/3d-field#rendering-modes). В случаях, когда упрощение приводит к нежелательным эффектам на пользовательских ресурсах, можно использовать два решения:

- Чтобы отключить автоматическое удаление конкретной меш-сетки, добавьте строку `NOSIMPLIFY` в имя меш-сетки.
- Чтобы отключить упрощение модели для всей модели робота, установите параметр `disableSimplification` в конфигурации в `true`.

:::

### Подвижные компоненты {#articulated-components}

:::warning
Настройка подвижных компонентов может быть сложной и отнимать много времени. Рассмотрите возможность использования [поддержки `Mechanism2d` в 3D](/tab-reference/3d-field#2d-mechanisms) в AdvantageScope, которая предлагает более простой подход к **визуализации механизмов на 3D-поле**.
:::

Модели роботов могут содержать подвижные компоненты для визуализации данных механизмов (подробнее см. [здесь](/tab-reference/3d-field)). Базовая модель glTF не должна содержать компонентов, а каждый компонент необходимо экспортировать как отдельную модель glTF. Модели компонентов именуются по шаблону «model_ИНДЕКС.glb», поэтому первый подвижный компонент будет называться «model_0.glb».

Конфигурация компонентов задаётся в конфигурационном файле робота в виде массива под ключом «components». Если пользователь не передаёт в AdvantageScope позы компонентов, модели компонентов позиционируются с использованием вращений и позиции робота по умолчанию (см. выше). Если позы компонентов переданы, к каждому компоненту применяются «обнулённые» вращения и позиция, чтобы привести его к началу координат робота, после чего применяются позы пользователя для перемещения каждого компонента в нужное положение на роботе.

:::tip
При позиционировании 3D-компонентов относительно робота начало системы координат совпадает с опубликованной позой робота. Обратите внимание, что эта поза обычно использует нулевую высоту, то есть плоскость пола, а НЕ днище робота (для типичного 2D-движения робота).
:::

```json
"components": [
  {
    "zeroedRotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
    "zeroedPosition": [number, number, number] // Смещение позиции в метрах относительно робота, применяемое после вращения
  }
]
```

#### Процесс настройки {#setup-process}

Для калибровки позиций подвижных компонентов мы рекомендуем следующий порядок действий:

1. Экспортируйте базовую модель и компоненты в их правильных позициях «по умолчанию». Именно так они должны отображаться, если в AdvantageScope не переданы позы компонентов.

2. Опубликуйте обнулённую 2D-позу из кода робота, затем выберите её в качестве позы робота в AdvantageScope. Переключитесь на 3D-поле «Оси», которое показывает начало координат поля.

3. Настраивайте общие вращения робота (не компонентов), пока весь робот не будет ориентирован правильно. Затем настройте общую позицию, чтобы привести всего робота к началу координат. На протяжении всего этого этапа компоненты должны отображаться в своих позициях по умолчанию.

4. Опубликуйте из кода робота массив обнулённых 3D-поз, соответствующий количеству компонентов в модели, затем выберите его в качестве набора поз компонентов в AdvantageScope.

5. Настройте вращения, а затем позиции для каждого компонента, пока они не будут выровнены по началу координат. Например, сегмент рычага выравнивается так, чтобы точка вращения находилась в начале координат, а сам сегмент был направлен вперёд вдоль оси X.

6. Опубликуйте реальные позы компонентов из кода робота — они будут отсчитываться от вновь заданных начал координат для каждого компонента. Например, поза для сегмента рычага должна располагаться в шарнире рычага и быть направлена вдоль сегмента.

## Джойстики {#joysticks}

Изображение должно находиться в папке под именем «image.png». Конфигурационный файл должен иметь следующий формат:

```json
{
  "name": string // Уникальное имя, требуется для всех типов ресурсов
  "locales": { [locale: string]: string } // Необязательные переводы для имени ресурса
  "components": [...] // Массив конфигураций компонентов, см. ниже
}
```

:::info
Кнопки, джойстики и значения осей поддерживают привязки [SDL](https://www.libsdl.org) (используемые текущим FIRST Driver Station) и привязки NI (используемые старым NI FRC Driver Station). Для каждого компонента должен быть предоставлен хотя бы один набор привязок.

Для привязок NI AdvantageScope обратно совместим со старыми ключами конфигурации без префиксов (например, `sourceIndex`). **Все новые джойстики должны использовать явные привязки SDL (например, `sdlSourceIndex`) для совместимости с текущим FIRST Driver Station.**
:::

### Одиночная кнопка / значение POV {#single-button-pov-value}

```json
{
  "type": "button"
  "isYellow": boolean
  "isEllipse": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number
  "sdlSourcePov": string // Необязательно, может быть "up", "right", "down" или "left". Если предоставлено, "sdlSourceIndex" будет индексом POV для чтения.

  // Альтернативные привязки для NI Driver Station (необязательно)
  "niSourceIndex": number
  "niSourcePov": string
}
```

### Двухосевой джойстик {#two-axis-joystick}

```json
{
  "type": "joystick" // Джойстик, перемещающийся в двух измерениях
  "isYellow": boolean
  "centerPx": [number, number]
  "radiusPx": number
  "sdlXSourceIndex": number
  "sdlXSourceInverted": boolean // Не инвертировано: вправо = положительное
  "sdlYSourceIndex": number
  "sdlYSourceInverted": boolean // Не инвертировано: вверх = положительное
  "sdlButtonSourceIndex": number // Необязательно

  // Альтернативные привязки для NI Driver Station (необязательно)
  "niXSourceIndex": number
  "niXSourceInverted": boolean
  "niYSourceIndex": number
  "niYSourceInverted": boolean
  "niButtonSourceIndex": number
}
```

### Одиночная ось {#single-axis}

```json
{
  "type": "axis" // Значение одной оси
  "isYellow": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number,
  "sdlSourceRange": [number, number] // Мин больше макс для инвертирования

  // Альтернативные привязки для NI Driver Station (необязательно)
  "niSourceIndex": number,
  "niSourceRange": [number, number]
}
```

### Тачпад {#touchpad}

```json
{
  "type": "touchpad" // Тачпад
  "isYellow": boolean
  "centerPx": [number, number]
  "sizePx": [number, number]
  "sdlSourceIndex": number,
}
```

## Плоские изображения полей {#flat-field-images}

Изображение должно находиться в папке под именем «image.png» и быть ориентировано так, чтобы красный альянс располагался слева. Конфигурационный файл должен иметь следующий формат:

```json
{
  "name": string // Уникальное имя, требуется для всех типов ресурсов
  "locales": { [locale: string]: string } // Необязательные переводы для имени ресурса
  "isFTC": boolean // Является ли это полем FTC вместо поля FRC
  "coordinateSystem": // Система координат по умолчанию для использования (см. ниже)
      "wall-alliance" |  // FRC 2022
      "wall-blue" |      // FRC 2023-2026
      "center-rotated" | // FTC традиционная
      "center-red"       // Systemcore
  "useGrid": boolean // Отображать ли линии сетки, если это поле FTC (по умолчанию "true")
  "sourceUrl": string // Ссылка на оригинальный файл, необязательно
  "topLeft": [number, number] // Пиксельная координата (начало в верхнем левом углу)
  "bottomRight": [number, number] // Пиксельная координата (начало в верхнем левом углу)
  "widthInches": number // Реальная ширина поля (длинная сторона)
  "heightInches": number // Реальная высота поля (короткая сторона)
}
```

## 3D-модели полей {#3d-field-models}

Модель должна находиться в папке под именем «model.glb». После применения всех вращений поле должно быть ориентировано так, чтобы красный альянс располагался слева. Файлы CAD необходимо преобразовать в glTF; подробности см. на [этой странице](gltf-convert). Модели игровых элементов именуются по шаблону «model_ИНДЕКС.glb» в соответствии с порядком их перечисления в массиве «gamePieces». Объявленные здесь AprilTag всегда позиционируются в системе координат [центр/красные](/more-features/coordinate-systems#center-red), независимо от любых других параметров конфигурации.

Конфигурационный файл должен иметь следующий формат:

```json
{
  "name": string // Уникальное имя, требуется для всех типов ресурсов
  "locales": { [locale: string]: string } // Необязательные переводы для имени ресурса
  "isFTC": boolean // Является ли это полем FTC вместо поля FRC
  "coordinateSystem": // Система координат по умолчанию для использования (см. ниже)
      "wall-alliance" |  // FRC 2022
      "wall-blue" |      // FRC 2023-2026
      "center-rotated" | // FTC традиционная
      "center-red"       // Systemcore
  "useGrid": boolean // Отображать ли линии сетки, если это поле FTC (по умолчанию "true")
  "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
  "widthInches": number // Реальная ширина поля (длинная сторона)
  "heightInches": number // Реальная высота поля (короткая сторона)
  "defaultOrigin": "auto" | "blue" | "red" // Местоположение начала координат по умолчанию, "auto", если не указано
  "driverStations": [
    [number, number] // Позиции станций управления (X и Y в метрах относительно центра поля)
    ...              // Для FRC 6 элементов в порядке [B1, B2, B3, R1, R2, R3]. Для FTC 4 элемента в порядке [BL, BR, RL, RR].
  ]
  "gamePieces": [ // Список типов игровых элементов
    {
      "name": string // Имя игрового элемента
      "locales": { [locale: string]: string } // Необязательные переводы для имени игрового элемента
      "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
      "position": [number, number, number] // Смещение позиции в метрах, применяемое после вращения
      "stagedObjects": string[] // Имена размещённых объектов игровых элементов для скрытия при наличии поз пользователя
    },
    ...
  ],
  "aprilTags": [ // Список дополнительных моделей AprilTag (если не являются частью модели поля)
    "variant": string // Формат "FAMILY-SIZEin", где "FAMILY" — это "36h11" или "16h5", а "SIZE" — длина чёрной секции
    "id": number
    "rotations": { "axis": "x" | "y" | "z", "degrees": number }[] // Последовательность вращений вдоль осей x, y и z
    "position": [number, number, number] // Смещение позиции в метрах, применяемое после вращения
  ]
}
```
