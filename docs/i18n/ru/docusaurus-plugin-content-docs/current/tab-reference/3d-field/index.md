# 👀 3D-поле {#3d-field}

3D-поле показывает 3D-визуализацию робота и поля. Его можно использовать с обычными 2D-позами, но оно особенно полезно при работе с 3D-вычислениями (такими как локализация с помощью AprilTag). Доступны несколько видов камер, включая относительно поля, относительно робота и фиксированные. [AdvantageScope XR](advantagescope-xr) позволяет визуализировать эту вкладку с использованием дополненной реальности. Шкала времени показывает, когда робот включен, и может использоваться для навигации по данным лога.

<img src="/img/tab-reference/3d-field/3d-field-1.png" alt="Example of 3D field tab" />

<details>
<summary>Элементы управления шкалой времени</summary>

Шкала времени используется для управления воспроизведением и визуализацией. Щелчок по шкале времени выбирает время, а щелчок правой кнопкой мыши отменяет его выбор. Выбранное время синхронизируется на всех вкладках, что позволяет легко найти это место в других видах.

Желтые секции указывают, когда робот находится в автономном режиме, синие секции указывают, когда робот находится в телеуправляемом режиме, а серые секции указывают, когда робот находится в служебном режиме.

Чтобы изменить масштаб, поместите курсор на шкалу времени и прокрутите вверх или вниз. Диапазон также можно выбрать щелчком и перетаскиванием с удержанием `Shift`. Перемещайтесь влево и вправо путем горизонтальной прокрутки (на поддерживаемых устройствах) или путем щелчка и перетаскивания на шкале времени. При подключении в реальном времени прокрутка влево отвязывает от текущего времени, а прокрутка до упора вправо снова привязывает к текущему времени. Нажмите `Ctrl+\`, чтобы масштабировать до периода, когда робот включен.

<img src="/img/tab-reference/timeline.png" alt="Timeline" />

</details>

:::warning
Модель поля FRC 2026 года соответствует раскладке AprilTag для **сварного** поля. Различия между сварным полем и полем AndyMark очень незначительны, но могут быть небольшие расхождения (~0,5 дюйма) при визуализации поз AprilTag на основе раскладки поля AndyMark.
:::

## Добавление объектов {#adding-objects}

Чтобы начать работу, перетащите поле в раздел «Позы». Удалите объект с помощью кнопки X или временно скройте его, нажав иконку глаза или дважды щелкнув имя поля. Чтобы удалить все объекты, нажмите на мусорную корзину рядом с заголовком оси, а затем `Очистить все`. Объекты можно переупорядочивать в списке путем щелчка и перетаскивания.

**Чтобы настроить каждый объект, нажмите на цветную иконку или щелкните правой кнопкой мыши по имени поля.** AdvantageScope поддерживает большое количество типов объектов, многие из которых можно настраивать (например, менять цвета и модели роботов). Некоторые объекты должны быть добавлены как дочерние элементы к существующему объекту.

:::tip
Чтобы увидеть полный список поддерживаемых типов объектов, нажмите иконку `?`. Этот список также включает поддерживаемые типы данных и то, должны ли объекты добавляться как дочерние элементы.
:::

:::info
AdvantageScope поддерживает несколько размеров AprilTag для полей FTC. Размеры измеряются как **длина стороны черной секции AprilTag**, не включая требуемую белую рамку.
:::

## Формат данных {#data-format}

Данные геометрии должны публиковаться в виде закодированных в байты структур (struct) или protobuf. Поддерживаются различные 2D- и 3D-типы геометрии, включая `Pose2d`, `Pose3d`, `Translation2d`, `Translation3d` и другие.

Многие библиотеки поддерживают формат struct, включая WPILib и AdvantageKit. Пример кода ниже показывает, как логировать данные 3D-позы на Java.

<Tabs groupId="library">
<TabItem value="wpilib" label="WPILib" default>

```java
Pose3d poseA = new Pose3d();
Pose3d poseB = new Pose3d();

StructPublisher<Pose3d> publisher = NetworkTableInstance.getDefault()
  .getStructTopic("MyPose", Pose3d.struct).publish();
StructArrayPublisher<Pose3d> arrayPublisher = NetworkTableInstance.getDefault()
  .getStructArrayTopic("MyPoseArray", Pose3d.struct).publish();

periodic() {
  publisher.set(poseA);
  arrayPublisher.set(new Pose3d[] {poseA, poseB});
}
```

:::tip
Класс WPILib [`Field2d`](https://docs.wpilib.org/en/stable/docs/software/dashboards/glass/field2d-widget.html) также может использоваться для совместного логирования нескольких наборов данных 2D-поз.
:::

</TabItem>
<TabItem value="advantagekit" label="AdvantageKit">

```java
Pose3d poseA = new Pose3d();
Pose3d poseB = new Pose3d();

Logger.recordOutput("MyPose", poseA);
Logger.recordOutput("MyPoseArray", poseA, poseB);
Logger.recordOutput("MyPoseArray", new Pose3d[] {poseA, poseB});
```

</TabItem>
<TabItem value="ftcdashboard" label="FTC Dashboard">

```java
// Этот протокол не поддерживает современный формат struct, но значения
// позы могут публиковаться с использованием отдельных полей, включающих
// суффиксы "x", "y" и "heading" (как показано ниже):
TelemetryPacket packet = new TelemetryPacket();
packet.put("Pose x", 6.3); // Дюймы
packet.put("Pose y", 2.8); // Дюймы
packet.put("Pose heading", 3.14); // Радианы

// Альтернативно, направления могут публиковаться в градусах
packet.put("Pose heading (deg)", 180.0); // Градусы
```

</TabItem>

## Механизмы и компоненты {#mechanisms-and-components}

Данные механизмов можно визуализировать с помощью 2D-механизмов или артикулированных 3D-компонентов.

### 2D-механизмы {#2d-mechanisms}

Чтобы визуализировать данные механизма, записанные с помощью [`Mechanism2d`](https://docs.wpilib.org/en/stable/docs/software/dashboards/glass/mech2d-widget.html), добавьте поле механизма к существующему объекту робота или призрака. Механизм проецируется на плоскость XZ или YZ робота с помощью простых прямоугольников, как показано ниже. Нажмите иконку шестеренки или щелкните правой кнопкой мыши по имени поля для переключения между плоскостями XZ и YZ. Начало координат робота центрировано по нижнему краю механизма.

<img src="/img/tab-reference/3d-field/3d-field-2.png" alt="2D mechanism" />

### 3D-компоненты {#3d-components}

:::warning
Настройка 3D-компонентов может быть сложной и отнимать много времени. Рассмотрите возможность использования поддержки `Mechanism2d` в AdvantageScope, как описано выше, что предлагает более простой подход к визуализации механизмов на 3D-поле.
:::

Механизмы можно визуализировать с помощью артикулированных компонентов путем логирования набора 3D-поз, представляющих расположения каждого компонента относительно робота. Добавьте позы к существующему объекту робота или призрака и установите тип объекта «Компонент».

Каждый компонент можно перемещать независимо (например, каретку элеватора, рычаг или захват). Пользователям AdvantageKit следует рассмотреть возможность использования метода [`generate3dMechanism()`](https://docs.advantagekit.org/data-flow/supported-types#mechanisms-output-only) для преобразования Mechanism2d в массив объектов Pose3d. Для получения дополнительной информации о настройке роботов с компонентами смотрите [Пользовательские ресурсы](/more-features/custom-assets).

<img src="/img/tab-reference/3d-field/3d-field-3.png" alt="3D mechanism" />

## Объекты игровых элементов {#game-piece-objects}

Каждое поле включает набор типов объектов игровых элементов, что позволяет рендерить игровые элементы в любой позиции на поле с использованием данных, опубликованных кодом робота. Это имеет множество применений, включая:

- Визуализацию действий симулируемых автопрограмм с использованием простых анимаций
- Отображение обнаруженных расположений игровых элементов на поле
- Индикацию того, где игровые элементы находятся внутри робота
- Просмотр траекторий выстрелов на основе физических расчетов

Еще один простой вариант использования — отображение состояния игровых элементов внутри робота на основе данных датчиков. Например, датчик прерывания луча на пути ноты для робота 2024 года может приводить к появлению ноты (как показано ниже).

## Опции камеры {#camera-options}

Чтобы переключить выбранный режим камеры, щелкните правой кнопкой мыши по срендеренному виду поля. Режим камеры и позиция управляются независимо для каждого всплывающего окна, что позволяет легко создавать виды с нескольких камер.

:::info
Щелкните правой кнопкой мыши по срендеренному виду поля и нажмите «Установить поле зрения...», чтобы настроить поле зрения облетающих камер и камер станции управления.
:::

### Облет поля {#orbit-field}

Это режим камеры по умолчанию, в котором камеру можно свободно перемещать относительно поля. **ЛКМ + перетаскивание** вращает камеру, а **ПКМ + перетаскивание** панорамирует камеру. **Прокрутка** изменяет масштаб.

:::tip
Камерой также можно управлять с помощью клавиатуры. Клавиши **WASD** используются для перемещения, клавиши **IJKL** используются для вращения, а клавиши **E** и **Q** используются для вертикального перемещения.
:::

### Облет робота {#orbit-robot}

Этот режим имеет те же элементы управления, что и режим «Облет поля», но позиция камеры заблокирована относительно робота. Это позволяет осуществлять «следящую» съемку движения робота.

### Станция управления {#driver-station}

Этот режим блокирует камеру за одной из станций управления на типичной высоте глаз. Выберите станцию для просмотра вручную или выберите «Авто», чтобы использовать альянс и номер станции, сохраненные в данных лога.

:::warning
Автоматический выбор номера станции может быть неточным при просмотре данных логов, созданных AdvantageKit 2023 или более ранней версии.
:::

### Фиксированная камера {#fixed-camera}

Каждая модель робота настроена с набором фиксированных камер, таких как камеры зрения и камеры водителя. Эти камеры имеют фиксированные позиции, соотношения сторон и поля зрения. Эти виды часто полезны для проверки данных зрения или для имитации вида с камеры водителя. В примере ниже показана камера водителя.

<img src="/img/tab-reference/3d-field/3d-field-5.png" alt="Fixed camera" />

Если предоставлена поза «Переопределения камеры», она заменяет позы по умолчанию всех фиксированных камер, сохраняя их настроенные поля зрения и соотношения сторон. Это позволяет коду робота предоставлять позицию подвижной камеры, такой как камера, установленная на турели или кожухе шутера.

:::info
В соответствии с другими данными поз, поза «Переопределения камеры» должна быть _относительно поля_, а не относительно робота.
:::

## Конфигурация {#configuration}

Модель поля можно настроить с помощью выпадающего списка. Поддерживаются все недавние игры FRC и FTC. Мы рекомендуем использовать поля «Evergreen» для устройств с ограниченной графической производительностью. Поля «Оси» отображают только оси XYZ в начале координат с контуром поля для масштаба.

:::info
Система координат, используемая на этой вкладке, настраивается. Смотрите страницу [системы координат](/more-features/coordinate-systems) для получения подробной информации.
:::

### Режимы рендеринга {#rendering-modes}

3D-поле поддерживает три режима рендеринга:

- **Кинематографичный:** Рендеринг с использованием теней, освещения, отражений и высокодетализированных 3D-моделей для более реалистичного вида. Требует достаточно мощного GPU.
- **Стандартный (по умолчанию):** Рендеринг с минимальным освещением и упрощенными 3D-моделями. Хорошо работает на большинстве устройств.
- **Низкое энергопотребление:** Снижение частоты кадров, разрешения и детализации моделей для уменьшения потребления батареи и обеспечения более стабильной производительности на слабых устройствах.

<img src="/img/tab-reference/3d-field/3d-field-6.png" alt="Comparion of rendering modes" />

Чтобы настроить режим рендеринга, откройте окно настроек, нажав **Приложение > Показать настройки...** (Windows/Linux) или **AdvantageScope > Настройки...** (macOS). Настройку «3D-режим (от батареи)» можно переключить с режима по умолчанию, чтобы переопределить режим рендеринга, используемый на ноутбуке при работе не от сети. Например, это можно использовать для экономии батареи во время соревнований.
